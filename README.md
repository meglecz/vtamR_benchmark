### bat

This dataset is from [Galan et al. (2017)](https://onlinelibrary.wiley.com/doi/10.1111/1755-0998.12749) and contains COI sequences from bat faecal samples.

Download the FASTQ files from <https://datadryad.org/stash/dataset/doi:10.5061/dryad.kv02g>, extract the archive, and move the FASTQ files to **data/fastq/bat**.

The FASTQ files have already been demultiplexed, but the primers must be trimmed. This can be handled by **vtamR**, but not by **VTAM**. Use vtamR to prepare the files for filtering by:

- trimming the primers and writing the output to **data/fastq/bat/demultiplex_trim**
- converting **sampleinfo.csv** to **sortedinfo.tsv** for VTAM

The preprocessing runtime is recorded (**runtime_preprocess_bat.csv**) but is **not included** in the pipeline comparison because this step cannot be performed by VTAM.

```
bash ./scripts/preprocess_bat.sh
```

### fish

This dataset is from [Corse et al. (2017)](https://onlinelibrary.wiley.com/doi/10.1111/1755-0998.12703) and contains COI sequences from faecal samples of *Zingel asper*. Each sample was amplified with two primer pairs (**mfzr** and **zfzr**) producing strongly overlapping amplicons.

Download the FASTQ files from <https://datadryad.org/stash/dataset/doi:10.5061/dryad.f40v5>, extract the archive, and move the FASTQ files to:

- **data/fastq/fish_mfzr**
- **data/fastq/fish_zfzr**

These files can be used directly by both VTAM and vtamR.

### shark

This dataset is from [Esposito et al. (2022)](https://www.mdpi.com/2410-3888/7/6/312) and contains 16S sequences from shark stomach contents.

Download the FASTQ files from <https://osf.io/3txv7/overview>, extract the archive, and move the FASTQ files to:

- **data/fastq/shark/200309**
- **data/fastq/shark/200513**

The two sequencing runs must be pooled before analysis. This step can be performed by vtamR, and the resulting files can be used by both VTAM and vtamR.

The runtime is recorded (**runtime_concatenate_shark.csv**) but is **not included** in the pipeline comparison.

```
bash ./scripts/vtamR_concatenate_files.sh
```

## VTAM

Run the VTAM pipeline with the following steps:

- **merge**
  - skip for **bat** (use the output from `preprocess_bat.sh`)
- **sortreads**
  - skip for **bat** (use the output from `preprocess_bat.sh`)
- **filter** (default parameters)
  - use `sorteddir` and `sortedinfo` generated by vtamR for **bat**
  - use `lfn_variant_replicate` for **fish** and **shark**
  - skip `FilterIndel` and `FilterCodonStop` for **shark**
- **make_known_occurrences**
- **OptimizePCRerror**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
- **OptimizeLFNsampleReplicate**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
- **OptimizeLFNreadCountAndLFNvariant**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
  - use `lfn_variant_replicate` for **fish** and **shark**
  - use the optimized values for `lfn_sample_replicate_cutoff` and `pcr_error_var_prop`
- **taxassign**
  - skip for **shark**
- pool the **fish_mfzr** and **fish_zfzr** results

The following script runs the complete VTAM pipeline **10 times** for all four datasets (**bat**, **fish_mfzr**, **fish_zfzr**, and **shark**) and pools the fish primer-pair results.

**compare_filter.R**

Compares the final output files produced by VTAM and vtamR and identifies occurrences that are present in one output but absent from the other.

For these occurrences, the script generates files reporting their presence or absence at each filtering step of the pipeline in which they occur:

- occurrences_missing_in_vtam_DATASET.csv
- occurrences_missing_in_vtamR_DATASET.csv

It also generates a file containing the read counts from both pipelines for each occurrence detected in the final filtered outputs:

- read_count_VTAM_vtamR_DATASET.csv

~~~
Rscript scripts/compare_filter.R
~~~

**Conclusions**

There are only a small number of occurrences that differ between the two pipelines. All discrepancies originate from the *filter_chimera* or *filter_pcr_error* steps.

For PCR error and chimera filtering, vtamR removes a variant when it is classified as a PCR error in more than 80% of the samples in which it occurs. In contrast, VTAM processes samples independently and makes filtering decisions on a sample-by-sample basis, without enforcing a consistent decision for a given ASV across all samples.

As a result, when analyses are performed independently for each sample, obtaining exactly identical results between the two pipelines is not possible. However, we believe that the behavior implemented in vtamR is more biologically justified, since a given ASV is unlikely to represent an artefact in one sample while being a true biological variant in another.
