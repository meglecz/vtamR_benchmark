### bat

This dataset is from [Galan et al. (2017)](https://onlinelibrary.wiley.com/doi/10.1111/1755-0998.12749) and contains COI sequences from bat faecal samples.

Download the FASTQ files from <https://datadryad.org/stash/dataset/doi:10.5061/dryad.kv02g>, extract the archive, and move the FASTQ files to **data/fastq/bat**.

The FASTQ files have already been demultiplexed, but the primers must be trimmed. This can be handled by **vtamR**, but not by **VTAM**. Use vtamR to prepare the files for filtering by:

- trimming the primers and writing the output to **data/fastq/bat/demultiplex_trim**
- converting **sampleinfo.csv** to **sortedinfo.tsv** for VTAM

The preprocessing runtime is recorded (**runtime_preprocess_bat.csv**) but is **not included** in the pipeline comparison because this step cannot be performed by VTAM.

```
bash ./scripts/preprocess_bat.sh
```

### fish

This dataset is from [Corse et al. (2017)](https://onlinelibrary.wiley.com/doi/10.1111/1755-0998.12703) and contains COI sequences from faecal samples of *Zingel asper*. Each sample was amplified with two primer pairs (**mfzr** and **zfzr**) producing strongly overlapping amplicons.

Download the FASTQ files from <https://datadryad.org/stash/dataset/doi:10.5061/dryad.f40v5>, extract the archive, and move the FASTQ files to:

- **data/fastq/fish_mfzr**
- **data/fastq/fish_zfzr**

These files can be used directly by both VTAM and vtamR.

### shark

This dataset is from [Esposito et al. (2022)](https://www.mdpi.com/2410-3888/7/6/312) and contains 16S sequences from shark stomach contents.

Download the FASTQ files from <https://osf.io/3txv7/overview>, extract the archive, and move the FASTQ files to:

- **data/fastq/shark/200309**
- **data/fastq/shark/200513**

The two sequencing runs must be pooled before analysis. This step can be performed by vtamR, and the resulting files can be used by both VTAM and vtamR.

The runtime is recorded (**runtime_concatenate_shark.csv**) but is **not included** in the pipeline comparison.

```
bash ./scripts/vtamR_concatenate_files.sh
```

## VTAM

Run the VTAM pipeline with the following steps:

- **merge**
  - skip for **bat** (use the output from `preprocess_bat.sh`)
- **sortreads**
  - skip for **bat** (use the output from `preprocess_bat.sh`)
- **filter** (default parameters)
  - use `sorteddir` and `sortedinfo` generated by vtamR for **bat**
  - use `lfn_variant_replicate` for **fish** and **shark**
  - skip `FilterIndel` and `FilterCodonStop` for **shark**
- **make_known_occurrences**
- **OptimizePCRerror**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
- **OptimizeLFNsampleReplicate**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
- **OptimizeLFNreadCountAndLFNvariant**
  - use `sorteddir` and `sortedinfo` from vtamR for **bat**
  - use `lfn_variant_replicate` for **fish** and **shark**
  - use the optimized values for `lfn_sample_replicate_cutoff` and `pcr_error_var_prop`
- **taxassign**
  - skip for **shark**
- pool the **fish_mfzr** and **fish_zfzr** results

The following script runs the complete VTAM pipeline **10 times** for all four datasets (**bat**, **fish_mfzr**, **fish_zfzr**, and **shark**) and pools the fish primer-pair results.

```
bash ./scripts/vtam.sh
```

## vtamR

Run the following vtamR functions in an order that matches the VTAM pipeline as closely as possible.

### Preprocess

- `merge_fastq_pairs`
- `demultiplex_and_trim`
  - use `trim_primers` for **bat**

### Filtering

- filtering (default VTAM-equivalent parameters)
  - `dereplicate` (VTAM: included in `filter`)
  - `filter_asv_global` (VTAM: `global_read_count_cutoff`)
  - `filter_occurrence_sample` (VTAM: `LFN_sample_replicate`)
  - `filter_occurrence_variant`
    - VTAM: `LFN_variant_replicate` for **fish** and **shark**
    - VTAM: `LFN_variant` for **bat**
  - `filter_occurrence_read_count` (VTAM: `LFN_read_count`)
  - `pool_filters` (VTAM: Pool LFN)
  - `filter_min_replicate` (VTAM: `FilterMinReplicateNumber`)
  - `filter_pcr_error` (VTAM: `FilterPCRerror`)
  - `filter_chimera` (VTAM: `FilterChimera`)
  - `filter_min_replicate` (second pass)
  - `filter_replicate` (VTAM: `FilterRenkonen`)
  - `filter_min_replicate` (third pass)
  - `filter_indel` (VTAM: `FilterIndel`; skip for **shark**)
  - `filter_stop_codon` (VTAM: `FilterCodonStop`; skip for **shark**)
  - `pool_replicates` (VTAM: `ReadCountAverageOverReplicates`)
  - `write_asv_table` (VTAM: `MakeAsvTable`)
  - `classify_control_occurrences` (no VTAM equivalent)

### Parameter suggestion

- `suggest_sample_cutoff`
  - on unfiltered data
  - corresponds to VTAM optimization up to `OptimizeLFNsampleReplicate`
- `suggest_pcr_error_cutoff`
  - on unfiltered data
  - corresponds to VTAM optimization up to `OptimizePCRerror`
- pre-filter using the optimized values
  - `filter_occurrence_sample`
  - `filter_pcr_error`
  - `pool_filters`
  - `filter_min_replicate`
- `classify_control_occurrences`
  - on pre-filtered data
  - corresponds to VTAM `make_known_occurrences`
- `suggest_variant_readcount_cutoffs`
  - on pre-filtered data
  - corresponds to VTAM optimization up to `OptimizeLFNreadCountAndLFNvariant`

### Taxonomic assignment

- `assign_taxonomy_rdp` for **shark**
- `assign_taxonomy_ltg` for all other datasets (VTAM: `taxassign`)

The following script runs the complete vtamR pipeline **10 times** for all four datasets (**bat**, **fish_mfzr**, **fish_zfzr**, and **shark**) and pools the fish primer-pair results.

The complete list of ASVs (`variant`) and ASV identifiers (`asv_id`) extracted from the VTAM database is used to ensure **consistent ASV IDs across both pipelines**.

```
bash ./scripts/vtamR.sh
```


## Compare VTAM and vtamR output

### Merge and demultiplex

`compare_preprocess.R`

Output:

**comparaison_results/preprocess/preprocess_read_counts.csv**

The `merge`/`merge_and_trim` and `sortreads`/`demultiplex_and_trim` steps from VTAM and vtamR produce files with the same number of sequences. The only exception is a single read difference:

| filename           | read_count_vtam | read_count_vtamr | dataset   | step             |
| ------------------ | --------------- | ---------------- | --------- | ---------------- |
| 14Cro13-1.fasta.gz | 41538           | 41539            | fish_mfzr | demultiplex_trim |

### Filter

`compare_filter.R`

This script compares the final output files produced by VTAM and vtamR and identifies occurrences that are present in one output but absent from the other.

The output (**comparaison_results/filter/filter_read_counts.csv**) lists all occurrences of all datasets for both pipelines.  

The only difference is in the 14Cro13 sample of the fish_mfzr dataset, whete the read counts differ by one between vtamR and VTAM (7757 in VTAM, 7758 in vtamR). This stems from the only differente at the demultiplexing steps.

### Taxassign

`compare_taxassign.R`

The proportion of the number of ASV with different taxonomic assignments between VTAM and vtamR is low (1.9–3.3%) as shown in **comparaison_results/taxassign/taxassign_summary.csv**

| dataset   | number_of_asv | number_of_differences | proportion |
| --------- | ------------- | --------------------- | ---------- |
| fish_mfzr | 153           | 5                     | 0.033      |
| fish_zfzr | 105           | 2                     | 0.019      |
| bat       | 1676          | 38                    | 0.023      |

**comparaison_results/taxassign/taxassign_differences.csv**: 

Most of these assignments occur at ≤80% identity, and are therefore uncertain in any case. In most cases, the ASV is unassigned by vtamR (32/45) or VTAM (2/45). When they are assigned by both pipelines, in 9 or 11 cases, the assignment differs only by the resolution. 

### Pool markers

`compare_pool_markers.R`

The VTAM `pool` function and the vtamR `pool_markers` function produce identical results.

**comparaison_results/pool_markers/pool_markers_read_counts.csv**

### Runtime

`compare_runtime.R`

For almost all steps and datasets, vtamR is faster than VTAM, both in terms of elapsed time and total CPU time.

Overall, the complete pipeline for 4 datasest requires:

* **4481 seconds** for vtamR (mean over 10 runs)
* **6421 seconds** for VTAM (mean over 10 runs)

Thus, vtamR reduces the overall runtime by approximately **30%**.
